# API Specification

Use the Tabular AI Orchestration Prediction API to submit inference requests, configure context selection strategies and generate classification or regression predictions with supported tabular foundation models.



## API Specification

Tabular AI Orchestration exposes a single prediction endpoint for inference requests.

```
curl POST "$DEPLOYMENT_URL/v1/predict"
```

**Data orientation**: Provide query data in only one format, either `column`or `rows` . Do not provide both formats in the same request. Provide context data in the same format as the query data. For example, if you use `columns`, provide context data in `contextColumns`not `contextRows` For more information, see [Data Format Requirement](https://github.tools.sap/AI/tabular-ai-orchestration/blob/main/docs/tabular_orchestration_v2.md#context-data-format-requirements).

**Context selection strategy configurations**: For information about the parameters available for each context selection strategy, see [Content Selection Strategy Configurations](https://github.tools.sap/AI/tabular-ai-orchestration/blob/main/docs/tabular_orchestration_v2.md#context-selection-strategy-configurations).

**Prediction configurations**: For information about the parameters available for each TFM, see the corresponding TFM documentation.

> ### Note:  
> Provide query data using either `columns` or `rows`, but not both.



## Input Validation

The API validates requests at two levels:

**Schema Validation**

-   Data format: Provide exactly one query data format, either `columns` or `rows`.
-   Context format: Use `contextColumns` with columnar query data and `contextRows` with row-based query data.
-   Column consistency: In columnar format, all column arrays must contain the same number of values.
-   Row consistency: In row format, all row objects must contain the same set of keys.
-   Schema matching: Context data must use the same column names as the query data.
-   Minimum data: Provide at least one row or one column. Each column must contain at least one value.
-   Target columns: Specify at least one target column in `predictionConfig.targetColumns`.
-   `topK`: If specified, the value must be 1 or greater. This parameter is supported only for classification tasks.
-   `numRows`: If specified, the value must be 0 or greater.

**Business Logic Validation**

-   Model limits: The number of query rows must not exceed the model's maximum supported value. See \#supported\_models.
-   Model name: Use a supported TFM model name.
-   Strategy: Specify one of the supported strategies: `none`, `random`, `heuristic`, or `auto`.

> ### Note:  
> If validation fails, the API returns a `400 Bad Request` response with detailed error information.

## Context Data Formats

The service supports columnar and row-wise data formats.

**Columnar Format**

Columnar format represents data as an object where each key is a column name and each value is an array of values.

```
{
  "id": [1, 2, 3],
  "category": ["[PREDICT]", "[PREDICT]", "[PREDICT]"],
  "price": [99.99, 49.99, 29.99]
}
```

**Row-wise Format**

Row-wise format represents data as an array of objects where each object corresponds to a row.

```
[
  { "id": 1, "category": "[PREDICT]", "price": 99.99 },
  { "id": 2, "category": "[PREDICT]", "price": 49.99 },
  { "id": 3, "category": "[PREDICT]", "price": 29.99 }
]
```



## Context selection strategies

The `contextSelectionConfig.strategy` parameter controls how context rows are selected from a registered tabular artifact.

Supported values are:

-   `random`
-   `heuristic`
-   `none`
-   `auto`



## Random strategy

The random strategy randomly samples `numRows` from the tabular artifact.

This strategy is used by default.

Execution time remains relatively constant because performance does not significantly depend on the number of query rows or the number of columns.

**Use Case**: Use this strategy when you need fast and predictable response times.

## Heuristic strategy

The heuristic strategy selects context rows by scoring similarity between query rows and artifact rows.

The service automatically detects numeric, string, and date columns and applies the appropriate matching logic.

Execution time depends on:

-   Tabular artifact size
-   Number of query rows
-   Number of columns
-   Prediction configuration complexity

**Use Case**: Use this strategy to retrieve context rows that closely match the query rows based on numeric, text, or date features.

## Prediction task types

The orchestration service supports classification and regression prediction tasks.

Configure the task type for each target column by using `predictionConfig.targetColumns[*].taskType`.

The selected task type determines how the tabular foundation model interprets and predicts values for cells marked with a prediction placeholder.

For complete response payload examples, see the [Example Payloads for Inferencing: sap-rpt-1](example-payloads-for-inferencing-sap-rpt-1-399566e.md).

**Classification Predictions**

Use the classification task type when the target column contains categorical values such as product categories, job codes, or status values.

The model predicts a discrete label for each prediction placeholder.

Supported column types are string columns that contain a finite set of distinct values.

**Classification Configuration Example**

```

{
  "name": "jobcode",
  "predictionPlaceholder": "[PREDICT]",
  "taskType": "classification",
  "topK": 1
}

```

**Classification Response Example**

```

{
  "jobcode": [
    {
      "confidence": 0.53,
      "confidence_interval": null,
      "prediction": "AEng"
    }
  ],
  "requisition_id": 2927
}
            
```

-   `prediction` contains the predicted category.
-   `confidence` contains a confidence score between 0 and 1.
-   `confidence_interval` contains the confidence interval when available.

**Returning Multiple Predictions with topK**

Set `topK` to a value greater than 1 to return multiple ranked candidate predictions for a target column.

```

{
  "name": "jobcode",
  "taskType": "classification",
  "topK": 3
}
 
```

Returned candidates are ordered by confidence score in descending order.

**Regression Predictions**

Use the regression task type when the target column contains continuous numeric values such as prices, quantities, or scores.

The model predicts a numeric value for each prediction placeholder.

Supported column types are numeric columns, including integers and decimal values.

**Regression Configuration Example**

```

{
  "name": "price",
  "predictionPlaceholder": "[PREDICT]",
  "taskType": "regression"
}
            
```

> ### Note:  
> The topK parameter is not supported for regression tasks.

**Regression Response Example**

```

{
  "price": [
    {
      "confidence_interval": null,
      "prediction": 89.99
    }
  ],
  "id": 1
}
            
```

-   `prediction` contains the predicted numeric value.
-   `confidence_interval` contains the confidence interval when available.



The service supports nested filter conditions that combine multiple logical expressions.



## Multi-target Prediction

The orchestration service supports predicting multiple target columns within the same request.

Each target column can define its own prediction configuration, placeholder value, and task type. See [Example:3 Multi-target Prediction with context selection](https://github.tools.sap/AI/tabular-ai-orchestration/blob/main/docs/tabular_orchestration_v2.md#example-3-multi-target-prediction-with-context-selection) for a complete request and response.

```

"targetColumns": [
  { "name": "category", "taskType": "classification" },
  { "name": "price", "taskType": "regression" }
] 
```

> ### Note:  
> Multi-target prediction is supported only for the SAP RPT model family.

**Custom Prediction Placeholders**

You can define custom placeholder values for individual target columns.

```

{
  "targetColumns": [
    {
      "name": "category",
      "predictionPlaceholder": "[MISSING]",
      "taskType": "classification"
    },
    {
      "name": "price",
      "predictionPlaceholder": "???",
      "taskType": "regression"
    }
  ]
}
```

The service replaces cells containing the configured placeholder with predicted values generated by the selected model.
